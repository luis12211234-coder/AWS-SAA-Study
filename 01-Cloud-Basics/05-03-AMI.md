# Amazon Machine Image (AMI)

## Overview

**AMI (Amazon Machine Image)** 는 EC2 Instance를 생성하기 위한 이미지이다.

OS, Software, Configuration 등을 미리 구성하여 새로운 EC2를 빠르게 생성할 수 있다.

```text
Configured EC2
↓
Create AMI
↓
AMI
↓
Launch New EC2 Instances
```

예:

```text
Amazon Linux
+ Apache
+ Application
+ Configuration
+ Monitoring Tools
↓
AMI
↓
Ready-to-use EC2
```

핵심 장점:

```text
Pre-configured Environment
→ Faster Boot & Configuration
```

---

# 1. Types of AMI

EC2는 여러 출처의 AMI에서 실행할 수 있다.

### Public AMI

AWS 등이 제공하는 공개 이미지이다.

```text
AWS Public AMI
→ Amazon Linux 등
```

### Custom AMI

사용자가 직접 구성하고 관리하는 AMI이다.

```text
EC2
+ Software
+ Configuration
↓
Custom AMI
```

회사 표준 서버 환경을 반복해서 생성할 때 유용하다.

### AWS Marketplace AMI

다른 공급자가 구성하여 AWS Marketplace에서 제공하는 AMI이다.

```text
Third-party Software
+ Pre-configured Environment
↓
Marketplace AMI
```

---

# 2. Creating an AMI

EC2 Instance에서 Custom AMI를 만드는 기본 흐름:

```text
Launch EC2
↓
Customize Instance
↓
Stop Instance
↓
Create AMI
↓
EBS Snapshots Created
↓
AMI Ready
```

강의에서는 데이터 무결성을 위해
AMI 생성 전 Instance를 Stop하는 흐름을 사용한다.

AMI를 생성하는 과정에서는
연결된 EBS Volume의 **EBS Snapshot**이 생성된다.

```text
EC2
│
├─ OS
├─ Software
├─ Configuration
└─ EBS
     ↓
Create AMI
     ↓
AMI + EBS Snapshot
```

---

# 3. Launching EC2 from an AMI

생성한 AMI를 사용하여 새로운 EC2 Instance를 실행할 수 있다.

```text
Custom AMI
    │
    ├──→ EC2-A
    ├──→ EC2-B
    └──→ EC2-C
```

새 Instance마다 동일한 Software를 다시 설치할 필요가 없기 때문에
구성 시간을 줄일 수 있다.

---

# 4. AMI and Regions

AMI는 특정 AWS Region을 기준으로 생성된다.

필요한 경우 다른 Region으로 복사할 수 있다.

```text
Region A
AMI
 │
 │ Copy
 ▼
Region B
AMI
```

이를 통해 동일한 서버 환경을
다른 AWS Region에서도 사용할 수 있다.

---

# 5. AMI vs EBS Snapshot

둘은 비슷해 보이지만 목적이 다르다.

| | AMI | EBS Snapshot |
|---|---|---|
| 목적 | EC2 생성 | EBS Volume 백업 |
| 대상 | EC2 환경 | EBS 데이터 |
| 활용 | 동일 환경의 EC2 실행 | EBS Volume 복원 |
| 관계 | 생성 과정에서 Snapshot 사용 | AMI의 Storage 기반으로 활용 |

간단히:

```text
EBS Snapshot
→ Disk Backup

AMI
→ EC2 Template / Image
```

# 6. Hands-On

이번 실습에서는 먼저 EC2를 생성하고
User Data를 이용하여 Apache (`httpd`)를 설치했다.

```text
New EC2
↓
User Data
↓
Install Apache
↓
Wait for installation
↓
Web Server Ready
```

이 Instance를 기반으로 `DemoImage`라는 Custom AMI를 생성했다.

```text
Configured EC2
↓
Create Image
↓
DemoImage
```

이후 새로운 EC2를 `DemoImage`에서 실행했다.

```text
DemoImage
↓
Launch EC2
↓
Apache already installed
```

새로운 Instance의 User Data에서는
Apache를 다시 설치하지 않고 웹 페이지 파일만 생성했다.

```text
AMI
→ Apache already installed

User Data
→ Create / customize index file
```

결과적으로 Apache 설치 과정을 다시 수행하지 않아
새로운 EC2가 더 빠르게 준비되는 것을 확인했다.

---

# 7. Why AMI Is Useful

AMI의 핵심은 **반복되는 초기 설정을 미리 이미지에 포함하는 것**이다.

예:

```text
Without AMI

Launch EC2
↓
Install Software
↓
Configure Software
↓
Start Application
```

```text
With Custom AMI

Launch EC2 from AMI
↓
Already Configured
↓
Start Application
```

따라서 여러 EC2에 동일한 환경이 필요한 경우 유용하다.

# Japanese Summary

**AMI (Amazon Machine Image)** は、
EC2 Instanceを作成するためのイメージです。

OS、Software、Configurationなどを事前に設定できます。

```text
Configured EC2
↓
Create AMI
↓
Launch New EC2
```

主なAMI：

```text
Public AMI
Custom AMI
AWS Marketplace AMI
```

AMIを作成するとEBS Snapshotも作成されます。

AMIを利用するとSoftwareの再インストールなどを減らし、
EC2の起動・設定時間を短縮できます。

# English Summary

An **AMI (Amazon Machine Image)** is an image used to launch EC2 instances.

It can contain a pre-configured operating system, software, and configuration.

```text
Configured EC2
↓
Create AMI
↓
Launch New EC2
```

AMI types include:

```text
Public AMI
Custom AMI
AWS Marketplace AMI
```

Creating an AMI also creates EBS snapshots.

Using a pre-configured AMI reduces the time required to prepare new EC2 instances.

# Review Questions

### Q1. AMI란?

EC2 Instance를 생성하기 위한
Amazon Machine Image이다.

### Q2. AMI를 사용하는 주요 이유는?

Software와 Configuration을 미리 포함하여
새 EC2의 부팅 및 구성 시간을 줄일 수 있기 때문이다.

### Q3. AMI의 세 가지 주요 출처는?

```text
Public AMI
Custom AMI
AWS Marketplace AMI
```

### Q4. Custom AMI 생성 시 함께 생성되는 Storage Resource는?

```text
EBS Snapshot
```

### Q5. EBS Snapshot과 AMI의 핵심 차이는?

```text
EBS Snapshot
→ EBS Volume Backup

AMI
→ EC2 Instance를 생성하기 위한 Image
```

### Q6. 다른 Region에서 같은 AMI를 사용하려면?

AMI를 대상 Region으로 복사할 수 있다.
