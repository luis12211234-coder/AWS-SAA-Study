# S3 CORS

## 🇰🇷 1. CORS란?

CORS는 Cross-Origin Resource Sharing의 약자입니다.

Browser에서 한 Origin의 Web Page가 다른 Origin의 Resource에 접근할 때 이를 허용할지 결정하는 보안 메커니즘입니다.

```text
Origin A
   ↓
Browser
   ↓
Origin B Resource 요청
   ↓
CORS 확인
```

---

## 2. Origin이란?

Origin은 다음 세 요소의 조합입니다.

```text
Protocol
+
Host
+
Port
```

예:

```text
https://www.example.com:443
```

하나라도 다르면 다른 Origin이 될 수 있습니다.

```text
https://www.example.com
https://other.example.com

→ Different Origin
```

---

## 3. S3에서의 CORS

예를 들어 두 개의 S3 Static Website가 있다고 가정합니다.

```text
Bucket A
index.html

Bucket B
image.jpg
```

Browser가 Bucket A의 Web Page를 열고 Bucket B의 Resource를 요청하면 Cross-Origin Request가 발생합니다.

```text
Browser
   ↓
Bucket A / index.html
   ↓
Bucket B / image.jpg
   ↓
CORS 확인
```

Bucket B가 Origin A의 요청을 허용하도록 CORS를 구성해야 Browser가 Resource를 사용할 수 있습니다.

---

## 4. CORS 설정은 Resource를 제공하는 쪽에 한다

이 부분이 중요합니다.

```text
A → B의 Resource 요청
```

이라면 CORS 설정은 **B**에 존재해야 합니다.

```text
Bucket A
   │
   │ Request
   ▼
Bucket B
   │
   └─ CORS Configuration
```

즉:

> **Resource를 제공하는 Server가 어떤 Origin을 허용할지 결정합니다.**

---

## 5. Preflight Request

일부 Cross-Origin Request에서는 Browser가 실제 요청 전에 허용 여부를 먼저 확인합니다.

```text
Browser
   │
   │ OPTIONS
   ▼
Server B
   │
   │ CORS Response
   ▼
Browser
   │
   │ Actual Request
   ▼
Server B
```

이를 Preflight Request라고 합니다.

Server는 CORS Header를 통해 허용 가능한 Origin과 Method 등을 알려줍니다.

예:

```text
Access-Control-Allow-Origin
Access-Control-Allow-Methods
```

모든 CORS 요청에 Preflight가 필요한 것은 아닙니다.

단순한 요청(Simple Request)은 조건을 만족하면 별도의 Preflight 없이 실제 요청이 전송될 수 있습니다.

---

## 6. Allowed Origin

특정 Origin만 허용할 수 있습니다.

```text
https://example.com
```

또는 모든 Origin을 허용할 수도 있습니다.

```text
*
```

보안 요구사항에 따라 필요한 Origin만 허용하는 것이 일반적입니다.

---

## 7. CORS는 IAM 권한이 아니다

CORS는 Browser 기반 Cross-Origin 보안 메커니즘입니다.

```text
CORS
≠
IAM Authorization
```

CORS를 허용했다고 해서 Private S3 Object에 대한 IAM 권한이 자동으로 생기는 것은 아닙니다.

---

## 🎯 Exam Scenario

```text
S3 Static Website A
        +
S3 Bucket / Website B의 Resource
        +
Browser에서 Cross-Origin Error
        ↓
CORS Configuration
```

문제에서 다음 표현이 나오면 CORS를 생각합니다.

```text
Cross-Origin
Browser
Different Domain
Access-Control-Allow-Origin
OPTIONS Request
```

---

## 🔑 핵심 정리

```text
Origin
= Protocol + Host + Port

CORS
= 다른 Origin의 Resource 접근 허용 규칙

A → B 요청
→ B에 CORS 설정

Preflight
= 실제 요청 전 OPTIONS로 허용 여부 확인

CORS
≠ IAM Permission
```

한 줄 정리:

> **Browser가 다른 Origin의 S3 Resource를 요청한다면 Resource 제공 측의 CORS 설정을 확인한다.**

## 🇯🇵 日本語 Summary

CORSは、Web Browserが異なるOriginのResourceへアクセスするときに、そのRequestを許可するための仕組みです。

OriginはProtocol、Host、Portの組み合わせです。

S3では、Resourceを提供するBucket側にCORS Configurationを設定します。

Preflight Requestでは、Browserが実際のRequestを送る前にOPTIONS Requestで許可を確認します。

---

## 🇺🇸 English Summary

CORS controls whether a browser can access resources from a different origin.

An origin consists of the protocol, host, and port.

For S3, CORS configuration is applied to the bucket that provides the requested resource.

Some cross-origin requests use a preflight OPTIONS request before the actual request.
